# 平面肉鸽小游戏开发方案

## 1. 项目定位

这是一个面向浏览器的俯视角 2D Roguelite 游戏。玩家控制一个角色在随机房间中移动，自动或半自动使用武器，击败不断出现的敌人，获得经验并从随机升级中选择强化，最终击败 Boss。

目标不是第一版就做成完整商业游戏，而是先做出一个 5 分钟内能理解、10 分钟内能完成一局、失败后愿意重新开始的最小可玩版本。

## 2. 第一版范围

### 必须完成

1. WASD 或方向键移动。
2. 鼠标瞄准，角色自动发射基础子弹。
3. 敌人从房间边缘生成并追踪玩家。
4. 子弹、玩家和敌人的基础碰撞。
5. 敌人死亡后掉落经验球。
6. 经验达到阈值后暂停游戏并显示三选一升级。
7. 房间清空后开启出口。
8. 随机选择下一个房间。
9. 玩家生命值、受伤无敌时间和死亡界面。
10. 一个简单 Boss 和通关/失败状态。

### 第一版暂不做

- 登录、账号和云端存档
- 在线排行榜
- 多人联机
- 商店和付费系统
- 大型剧情、任务系统和复杂 NPC
- 复杂装备合成
- 服务端实时战斗

## 3. 核心游戏循环

```text
开始一局
  -> 进入随机房间
  -> 击败当前房间敌人
  -> 获取经验并选择升级
  -> 通过出口进入下一房间
  -> 逐渐提高敌人强度
  -> 进入 Boss 房间
  -> 胜利或死亡后重新开始
```

每一局都由随机种子决定房间和升级顺序。第一版可以先使用浏览器随机数，稳定的种子系统放到第二阶段。

## 4. 玩家与战斗设计

### 玩家初始属性

| 属性 | 初始值 | 说明 |
| --- | ---: | --- |
| 生命值 | 100 | 归零后本局结束 |
| 移动速度 | 180 | 像素/秒 |
| 基础伤害 | 10 | 子弹命中伤害 |
| 攻击间隔 | 450ms | 自动攻击频率 |
| 子弹速度 | 520 | 像素/秒 |
| 经验拾取范围 | 70 | 经验球自动吸附距离 |

### 第一批敌人

1. **追猎者**：生命低、速度快，负责制造压力。
2. **重甲者**：生命高、速度慢，需要优先处理或绕开。
3. **远程者**：保持距离并发射缓慢弹丸，迫使玩家移动。

### 第一批升级

- 锋利子弹：伤害提高 20%。
- 快速射击：攻击间隔减少 15%。
- 疾行：移动速度提高 12%。
- 穿透弹：子弹额外穿透一个敌人。
- 磁力：经验球拾取范围提高 35%。
- 火焰弹：命中后附加持续伤害。

升级应该以数据配置保存，升级效果使用统一的 `apply` 函数，避免把规则散落在场景代码中。

## 5. 房间和关卡结构

第一版使用固定尺寸的房间模板，随机选择房间内容，不立即制作复杂的程序化地图。

每个房间包含：

- 矩形边界和障碍物
- 敌人生成点
- 入口和出口
- 房间类型
- 敌人波次配置

推荐房间类型：

- 普通房：一到三波敌人。
- 奖励房：敌人较少，完成后获得一次额外选择。
- 精英房：敌人更强，奖励更好。
- Boss 房：锁门战斗，击败 Boss 后结束本局。

## 6. 技术架构

```text
src/
├─ main.ts                 # Phaser 游戏入口
├─ scenes/
│  ├─ BootScene.ts         # 资源和基础配置
│  ├─ MenuScene.ts         # 开始界面
│  ├─ GameScene.ts         # 主战斗场景
│  ├─ UpgradeScene.ts      # 升级选择界面
│  └─ GameOverScene.ts     # 死亡和通关界面
├─ entities/
│  ├─ Player.ts
│  ├─ Enemy.ts
│  ├─ Projectile.ts
│  └─ ExperienceOrb.ts
├─ systems/
│  ├─ EnemySpawner.ts
│  ├─ RoomGenerator.ts
│  ├─ UpgradeSystem.ts
│  └─ SaveSystem.ts
├─ data/
│  ├─ enemies.ts
│  ├─ weapons.ts
│  └─ upgrades.ts
└─ ui/
   ├─ Hud.ts
   └─ UpgradePanel.ts
```

### 模块职责

- `scenes` 负责游戏阶段和输入流程。
- `entities` 负责玩家、敌人和投射物的运行状态。
- `systems` 负责生成、升级、房间流程等跨实体逻辑。
- `data` 只保存可调整的数值和配置。
- `ui` 负责血条、经验条、升级面板等界面。

## 7. 开发里程碑

### M0：项目脚手架

- 初始化 Vite、TypeScript、Phaser。
- 配置 `pnpm dev` 和 `pnpm build`。
- 建立场景和目录结构。

### M1：最小战斗原型

- 玩家移动。
- 一个敌人追踪玩家。
- 鼠标瞄准和子弹碰撞。
- 生命值、受伤和死亡。

验收标准：打开网页后，玩家可以在 60 秒内移动、攻击并击败敌人。

### M2：肉鸽循环

- 经验球和等级。
- 三选一升级。
- 敌人波次。
- 房间清空和出口。

验收标准：一局至少可以完成三个房间，并且每次升级都能改变战斗感受。

### M3：内容和 Boss

- 三种敌人。
- 四种房间类型。
- 一个 Boss。
- 通关和失败界面。

验收标准：玩家可以完成一局 5 至 10 分钟的完整游戏。

### M4：体验优化

- 音效和背景音乐。
- 屏幕震动和受击反馈。
- 移动端虚拟摇杆。
- 暂停、重开和本地最高记录。
- 桌面端和手机端适配。

## 8. 部署方案

第一版是静态前端，推荐使用 GitHub + Cloudflare Pages：

```text
develop 开发并验证
  -> 合并到 master
  -> Cloudflare Pages 自动构建
  -> 绑定独立游戏域名
```

建议使用独立域名，例如 `game.voqz.de`。构建命令为 `pnpm build`，输出目录为 `dist`。

只有在增加在线排行榜、云端存档或多人联机后，才需要 VPS 后端和数据库。

## 9. 风险和取舍

- 第一版不使用大量外部素材，先用简单图形验证玩法，避免美术工作阻塞开发。
- 不把所有数值写死在场景中，方便后续调平衡。
- 不在第一阶段引入后端，减少部署和账号安全问题。
- 每个里程碑都必须能单独运行，避免最后才发现核心循环不可玩。

## 10. 第一条实现任务

创建 Phaser + TypeScript 项目，完成 `M1` 的三个动作：

1. 玩家可以用 WASD 移动。
2. 一个敌人可以追踪玩家。
3. 玩家可以朝鼠标方向自动发射子弹。

完成这三个动作后，再开始加入经验和升级系统。
